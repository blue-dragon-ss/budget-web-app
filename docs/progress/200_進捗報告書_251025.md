## 3. 統一例外ハンドリング（GlobalExceptionHandler）

### 実装クラス  
`com.example.minimal.exception.GlobalExceptionHandler`  
→ `@RestControllerAdvice` により全 API の例外を一元管理。

### ExceptionHandler 一覧

| HTTP | 対象例外 | errorCode | message（概要） | 備考 |
|------|-----------|------------|------------------|------|
| 400 | `MethodArgumentNotValidException` | `VAL-0000` | BeanValidation不正（@Valid） | field/message抽出済み |
| 400 | `BindException` | `VAL-0000` | パラメータバインド不正 |  |
| 400 | `ConstraintViolationException` | `VAL-0000` | メソッドレベル検証違反 |  |
| 400 | `HttpMessageNotReadableException` | `VAL-0001` | JSON形式不正 | detailsにクラス名を含む |
| 400 | `IllegalArgumentException` | `VAL-0002` | 不正引数（業務上不正値） | 例外メッセージを返却 |
| 409 | `DataIntegrityViolationException` | `VAL-0105` | 一意制約違反 | field固定 `"code"` |
| 500 | `Exception` | `SYS-0001` | サーバ内部エラー | detailsに例外クラス |

### エラーレスポンス形式（固定）

```json
{
  "timestamp": "2025-10-22T00:00:00Z",
  "traceId": "a1b2c3d4e5f6",
  "errorCode": "VAL-0000",
  "message": "入力値が不正です。",
  "field": "member.name",
  "details": []
}
```

> 備考：現状 `VAL-0000` は共通仮コードとして運用中。将来的に詳細化（例：`VAL-0101` 必須、`VAL-0102` 長さ 等）を計画。
