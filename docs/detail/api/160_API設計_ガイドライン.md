# 160_API設計_ガイドライン

## 1. 目的と範囲
本ガイドラインは、就活用システムの **第1段階（Members／Invoices／Payments の独立登録・参照）** における REST風API設計ルールを定めます。
詳細仕様・共通要素は「161_API共通仕様」を参照します。

---

## 2. 基本方針

| 項目 | 方針 |
|------|------|
| HTTPメソッド | **POSTに統一**（GET/PUT/DELETEは使用しない） |
| ベースパス | `/api/v1` |
| エンコーディング | JSON（UTF-8） |
| ID生成 | サーバ側で ULID 生成 |
| タイムゾーン | DBはUTC保存、APIはISO-8601（UTC） |
| 論理削除 | `deleted_at` により制御し、検索は未削除のみ対象 |
| バージョニング | 破壊的変更時に `/v2` を新設 |

---

## 3. API構成命名規則

| 操作 | パス例 |
|------|--------|
| 一覧検索 | `/search` |
| 単票取得 | `/get` |
| 新規登録 | `/create` |
| 更新 | `/update` |
| 論理削除 | `/delete` |
| 復元 | `/restore` |

例：`/api/v1/members/create`

---

## 4. リクエスト構成（概要）

- Content-Type: `application/json`
- ページング・ソート指定は共通仕様「161_API共通仕様 §2.1」参照
- Idempotencyキー（`X-Idempotency-Key`）を任意ヘッダで受け入れ（再送対策）

---

## 5. レスポンス構成（概要）

| 状況 | HTTPステータス | 内容 |
|------|----------------|------|
| 成功（create） | 201 | 作成リソース単票を返却 |
| 成功（update/get/search） | 200 | 更新・取得結果を返却 |
| バリデーションエラー | 400 | `VAL-FFRR` コード体系に基づく |
| 重複エラー | 409 | 一意制約違反（`VAL-xxxx`） |
| システムエラー | 500 | `SYS-xxxx` |

> ※ エラー構造や監査ログ、トレーシングは「161_API共通仕様」に準拠。

---

## 6. バリデーション・エラーコード

| 種別 | 概要 | コード例 |
|------|------|----------|
| VAL | 入力バリデーション | `VAL-0101`（必須） |
| BUS | 業務ルール | `BUS-0001` |
| SYS | システム障害 | `SYS-0001` |

フィールド番号（FF）は1刻み採番、ルール（RR）は以下：

| 番号 | 意味 |
|------|------|
| 01 | 必須 |
| 02 | 長さ |
| 03 | 形式 |
| 04 | 範囲 |
| 05 | 一意 |

---

## 7. セキュリティ・監査

- トレーシング用ヘッダ：`X-Trace-Id`
- 再送対策：`X-Idempotency-Key`
- 監査ログは「161_API共通仕様 §7」に従い、`traceId` と `idempotencyKey` を出力
