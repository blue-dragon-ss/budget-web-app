# 161_API共通仕様

## 1. 共通ヘッダ

| ヘッダ | 必須 | 説明 |
|--------|:--:|------|
| Content-Type | ✔ | `application/json` 固定 |
| Accept | ✔ | `application/json` |
| Authorization | △ | 認証導入時のみ |
| X-Trace-Id | △ | リクエスト間相関ID（UUID） |
| X-Idempotency-Key | △ | 再送対策（create系推奨） |

**Idempotency動作**
- `create`で同一キー受信時は重複登録せず前回結果を返却
- 実装はキーとレスポンス永続化または例外正規化で可

---

## 2. 共通リクエスト形式

### 2.1 検索（/search）
```json
{
  "filters": { },
  "page": 0,
  "size": 20,
  "sort": ["field,asc"]
}
```
- `page`: 0基点
- `size`: 1〜200（既定20）
- `sort`: `"field,asc|desc"` の配列

### 2.2 単票取得（/get）
```json
{ "id": "01ABC..." }
```

### 2.3 更新（/update）
- 未指定フィールドは変更なし
- `null` は Nullable項目のクリア

## 3. 共通レスポンス形式

### 3.1 単票成功
```json
{
  "id": "01ABC...",
  "code": "C001",
  "name": "山田太郎",
  "createdAt": "2025-10-22T00:00:00Z",
  "updatedAt": "2025-10-22T00:00:00Z",
  "traceId": "a1b2c3d4"
}
```

### 3.2 検索成功
```json
{
  "items": [ ],
  "page": 0,
  "size": 20,
  "total": 100,
  "sort": ["field,asc"],
  "traceId": "a1b2c3d4"
}
```

### 3.3 エラー
```json
{
  "timestamp": "2025-10-22T00:00:00Z",
  "traceId": "a1b2c3d4",
  "errorCode": "VAL-0101",
  "message": "必須項目です",
  "field": "code"
}
```

## 4. ステータスコード

| HTTP | 用途 |
|------|------|
| 200 | get/search/update成功 |
| 201 | create成功 |
| 400 | バリデーション |
| 409 | 一意制約 |
| 422 | 業務ルール |
| 500 | システムエラー |

---

## 5. バリデーションコード（VAL-FFRR）

### 5.1 FFの割り当て

| コード | フィールド | フィールドの内容 |
|--------|-------------|------|
| VAL-01XX | code | 会員コード |
| VAL-02XX | name | 会員名 |
| VAL-03XX | email | メールアドレス |
| VAL-04XX | note | 備考 |

### 5.2 RRの割り当て

| コード | エラー内容 |
|--------|-------------|
| VAL-XX01 | 必須 |
| VAL-XX02 | 長さ |
| VAL-XX03 | 形式 |
| VAL-XX05 | 一意 |

---

## 6. BUS / SYS エラー

| 種別 | 内容例 |
|------|--------|
| BUS-0001 | 状態不整合 |
| SYS-0001 | DB障害、外部連携失敗など |

---

## 7. ログ・監査・トレース

- すべてのレスポンスに `traceId` を付与
- 監査ログには以下を出力
  - 操作種別、主体（認証あり時）、対象ID、時刻、クライアントIP
  - `traceId`, `idempotencyKey`
- JSON構造ログ推奨

---

## 8. パフォーマンス・制限

- 1ページ最大200件
- createはIdempotency推奨
