# 160_入力バリデーション詳細（161_API共通仕様準拠）

本書は入力検証の**実装ガイド**であり、コード体系・HTTP運用は **161_API共通仕様** に従います。

---

## 1. 方針
- DTO層で Bean Validation（`@Valid` / `@NotBlank` / `@Size` / `@Pattern` / `@Email` 等）を適用
- **正規化**：`trim`、Unicode正規化（NFKC推奨）、`email` は小文字化
- 不正は 400 (VAL-FFRR)。**業務矛盾は 422（BUS）**。ユニーク違反は 409（VAL-0105）。

---

## 2. MembersCreateRequest DTO（参考）
| 項目 | 型 | 必須 | 制約 | VALコード例 |
|------|----|:--:|------|-------------|
| code | String | ✔ | `@NotBlank`, `@Size(max=50)`, `@Pattern("^[A-Z0-9_-]{1,50}$")` | `VAL-0101`/`0102`/`0103` |
| name | String | ✔ | `@NotBlank`, `@Size(max=200)` | `VAL-0201`/`0202` |
| email | String |  | `@Size(max=320)`, `@Email` | `VAL-0302`/`0303` |
| note | String |  | `@Size(max=10000)` | `VAL-0402` |

## 5. 相関チェック（例）
- `paidAmount > invoice.amount` → **422（BUS-xxxx）**  
- `invoice` が「入金済」状態で再入金登録 → **422（BUS-xxxx）**（※旧版の 409 記載を修正）

---

## 6. 実装の要点
- **未指定は変更なし**・`null` は Nullable のクリア（161 §2.3）。
- コントローラ層で `BindingResult` を使わず、例外を `@ControllerAdvice` に集約。
- **メッセージ束**は `ValidationMessages.properties` に定義。キーに `VAL-FFRR` を含めると運用が明確。
