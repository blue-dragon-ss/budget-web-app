# 150_例外・エラー応答詳細（161_API共通仕様準拠・改訂）

本書は **「161_API共通仕様」** を正として、例外とエラー応答の詳細運用を定義します。

---

## 1. エラーレスポンス フォーマット（固定）

```json
{
  "timestamp": "2025-10-22T00:00:00Z",
  "traceId": "a1b2c3d4e5f6",
  "errorCode": "VAL-0101",
  "message": "会員コードは必須です。",
  "field": "code",
  "details": ["validation failed at 'code'"]
}
```

- キー名は **161_API共通仕様 §3.3** に合わせて `errorCode` / `message` / `field` を使用
- すべてのエラー応答に `traceId` を付与（161 §7）

---

## 2. HTTPステータスの原則（161 §4）

| HTTP | 用途（代表例） |
|------|----------------|
| **200** | `/get` `/search` `/update` 成功 |
| **201** | `/create` 成功（単票返却） |
| **400** | バリデーション違反（必須/形式/長さ/範囲） |
| **409** | 一意制約・更新競合（DBユニーク違反 など） |
| **422** | 業務ルール違反（②段階以降で使用） |
| **500** | サーバ内部エラー（未捕捉・外部障害） |

---

## 3. エラーコード体系（161 §5/§6 に準拠）

### 3.1 バリデーション（VAL-FFRR）
- **FF：フィールド番号（1刻み）** … `01=code, 02=name, 03=email, 04=note`
- **RR：ルール** … `01必須 / 02長さ / 03形式 / 04範囲 / 05一意`

| コード | フィールド | 内容 |
|-------|-----------|------|
| VAL-0101 | code  | 必須 |
| VAL-0102 | code  | 長さ |
| VAL-0103 | code  | 形式（文字種等） |
| VAL-0105 | code  | 一意 |
| VAL-0201 | name  | 必須 |
| VAL-0202 | name  | 長さ |
| VAL-0302 | email | 長さ |
| VAL-0303 | email | 形式 |
| VAL-0402 | note  | 長さ |

> 旧版に存在した `VAL-000x` / 10刻み採番は **廃止**。FFRRへ統一。

### 3.2 業務ルール（BUS-xxxx）
- ②段階以降で使用（例：入金超過、状態矛盾 など）。
- 本段階では**定義のみ**として予約。

### 3.3 システム（SYS-xxxx）
- 例：`SYS-0001`（DB障害）、`SYS-0002`（未捕捉例外）、`SYS-0003`（外部API障害）、`SYS-0999`（catch-all）

---

## 4. 例外ハンドリングのマッピング

- フレームワーク層は **@ControllerAdvice** で一元化。

| 例外 | ステータス | errorCode（例） | 備考 |
|------|-----------|-----------------|------|
| `MethodArgumentNotValidException` | 400 | `VAL-****` | Bean Validation 由来 |
| `ConstraintViolationException` | 400 | `VAL-****` | パラメータ検証 |
| `DataIntegrityViolationException` | 409 | `VAL-0105` | **ユニーク違反**は409に正規化 |
| `OptimisticLockingFailureException` | 409 | `SYS-0002` | 更新競合（将来的なversion運用時） |
| `CustomBusinessException` | 422 | `BUS-****` | ②段階以降 |
| （その他） | 500 | `SYS-0999` | 予期せぬ例外 |

---

## 5. メッセージと詳細

- `message` はユーザー向け日本語の簡潔な文言。
- `details` は開発者向けの技術情報（SQLState や violated index 名など）。
- 個人情報・秘密情報は `details` に出力しない（161 §7準拠）。
