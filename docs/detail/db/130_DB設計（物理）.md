# ①用DB基本設計書（Members／Invoices／Payments）
*version: 0.1（2025-10-20 JST）*

---

## 1. 対象範囲（このドキュメントで定義するもの）
- 3エンティティ（Members／Invoices／Payments）の**物理設計**（PostgreSQL想定）
- 監査・論理削除の共通仕様
- 一意制約・チェック制約・索引設計（一覧・検索・レポートの最低限を担保）
- Flyway初期マイグレーション（V1）サンプルSQL
- 最低限レポート用の集計SQLサンプル

> **非対象**：請求⇄入金の関連（②以降）、配賦（③以降）、仮入金/会計期間（④以降）

---

## 2. 設計方針（共通設計）
- **オペークID**：アプリ側生成の **ULID（26文字）** を主キーとして採用  
  - 物理型：`char(26)`（大文字、ハイフンなし）  
  - 例：`01J8ZQ1WQ2KZ1SM0M1N9C3R5XQ`
  - 形式チェック：`CHECK (id ~ '^[0-9A-HJKMNP-TV-Z]{26}$')`
- **通貨・桁**：金額は **円（整数）**、`numeric(12,0)` を採用  
  - 請求額：0以上、入金額：1以上（チェック制約）
- **日時**：DBは **UTC** 保存（`timestamptz`）、アプリでJST表示
- **監査項目**（共通）  
  - `created_at timestamptz not null default now()`（UTC）
  - `created_by varchar(100)`（アカウント識別子／任意）
  - `updated_at timestamptz not null default now()`（UTC）
  - `updated_by varchar(100)`（任意）
- **論理削除**：`deleted_at timestamptz null`  
  - 未削除：`deleted_at IS NULL`  
  - 一意制約は **部分一意インデックス**（`WHERE deleted_at IS NULL`）で実現
- **命名規約（抜粋）**  
  - テーブル：`snake_case`、複数形（例：`members`,`invoices`,`payments`）
  - カラム：`snake_case`
  - インデックス：`ix_<table>__<col1>[_<col2>]`
  - 一意制約：`ux_<table>__<col1>[_<col2>]`
- **更新監査トリガ**：`updated_at` 自動更新トリガを全テーブルに適用

## 6. 部分一意・更新監査トリガ

### 6.1 目的
- 会員コードの一意性を **未削除レコードに限定**  
- `updated_at` を **自動更新**（手動更新漏れ防止）

### 6.2 実装（PostgreSQL）
- 部分一意：`CREATE UNIQUE INDEX ux_members__code_active ON members(code) WHERE deleted_at IS NULL;`
- 監査トリガ：共通関数 `set_updated_at()` を作成し、3表に `BEFORE UPDATE` で付与

---

## 7. 代表的ユースケースと索引整合
- Members：`code` 指定の単票参照 → `ux_members__code_active`
- Invoices：会員・期間（`invoice_date BETWEEN ? AND ?`） → `ix_invoices__member_id_invoice_date`
- Payments：会員・期間（`payment_date BETWEEN ? AND ?`） → `ix_payments__member_id_payment_date`

---

## 8. 最低限レポートSQL（会員×月の請求合計／入金合計：別集計）

```sql
-- 請求（月次・会員別）
SELECT
  i.member_id,
  date_trunc('month', i.invoice_date)::date AS month,
  SUM(i.amount) AS invoice_total
FROM v_invoices_active i
GROUP BY i.member_id, date_trunc('month', i.invoice_date)
ORDER BY month, member_id;

-- 入金（月次・会員別）
SELECT
  p.member_id,
  date_trunc('month', p.payment_date)::date AS month,
  SUM(p.amount) AS payment_total
FROM v_payments_active p
GROUP BY p.member_id, date_trunc('month', p.payment_date)
ORDER BY month, member_id;
```

> ※突合・残高算出は **②以降** で対応します（①では独立集計のみ）。

## 9. Flyway初期マイグレーション例（V1__init.sql）

```sql
-- ==== 共通: updated_at 自動更新トリガ ====
CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  NEW.updated_at := now();
  RETURN NEW;
END;
$$;

-- ==== members ====
CREATE TABLE members (
  id          char(26) PRIMARY KEY,
  code        varchar(50)  NOT NULL,
  name        varchar(200) NOT NULL,
  email       varchar(320),
  note        text,
  created_at  timestamptz  NOT NULL DEFAULT now(),
  created_by  varchar(100),
  updated_at  timestamptz  NOT NULL DEFAULT now(),
  updated_by  varchar(100),
  deleted_at  timestamptz,
  CONSTRAINT ck_members_id_ulid CHECK (id ~ '^[0-9A-HJKMNP-TV-Z]{26}$')
);

-- 未削除時の一意（会員コード）
CREATE UNIQUE INDEX ux_members__code_active ON members (code) WHERE deleted_at IS NULL;

-- LIKE検索用
CREATE INDEX ix_members__name ON members (name);

-- トリガ
CREATE TRIGGER trg_members_updated_at
BEFORE UPDATE ON members
FOR EACH ROW EXECUTE FUNCTION set_updated_at();

-- ==== invoices ====
CREATE TABLE invoices (
  id           char(26) PRIMARY KEY,
  member_id    char(26)     NOT NULL REFERENCES members(id),
  invoice_date date         NOT NULL,
  due_date     date,
  amount       numeric(12,0) NOT NULL,
  title        varchar(200) NOT NULL,
  description  text,
  status       varchar(20)  NOT NULL DEFAULT 'ISSUED',
  created_at   timestamptz  NOT NULL DEFAULT now(),
  created_by   varchar(100),
  updated_at   timestamptz  NOT NULL DEFAULT now(),
  updated_by   varchar(100),
  deleted_at   timestamptz,
  CONSTRAINT ck_invoices_id_ulid CHECK (id ~ '^[0-9A-HJKMNP-TV-Z]{26}$'),
  CONSTRAINT ck_invoices_amount_nonneg CHECK (amount >= 0)
);

CREATE INDEX ix_invoices__member_id_invoice_date ON invoices (member_id, invoice_date);
CREATE INDEX ix_invoices__invoice_date ON invoices (invoice_date);

CREATE TRIGGER trg_invoices_updated_at
BEFORE UPDATE ON invoices
FOR EACH ROW EXECUTE FUNCTION set_updated_at();

-- ==== payments ====
CREATE TABLE payments (
  id           char(26) PRIMARY KEY,
  member_id    char(26)     NOT NULL REFERENCES members(id),
  payment_date date         NOT NULL,
  amount       numeric(12,0) NOT NULL,
  method       varchar(30),
  ref_no       varchar(100),
  note         text,
  created_at   timestamptz  NOT NULL DEFAULT now(),
  created_by   varchar(100),
  updated_at   timestamptz  NOT NULL DEFAULT now(),
  updated_by   varchar(100),
  deleted_at   timestamptz,
  CONSTRAINT ck_payments_id_ulid CHECK (id ~ '^[0-9A-HJKMNP-TV-Z]{26}$'),
  CONSTRAINT ck_payments_amount_positive CHECK (amount >= 1)
);

CREATE INDEX ix_payments__member_id_payment_date ON payments (member_id, payment_date);
CREATE INDEX ix_payments__payment_date ON payments (payment_date);
CREATE INDEX ix_payments__method ON payments (method);

CREATE TRIGGER trg_payments_updated_at
BEFORE UPDATE ON payments
FOR EACH ROW EXECUTE FUNCTION set_updated_at();

-- ==== Activeビュー ====
CREATE VIEW v_members_active  AS SELECT * FROM members  WHERE deleted_at IS NULL;
CREATE VIEW v_invoices_active AS SELECT * FROM invoices WHERE deleted_at IS NULL;
CREATE VIEW v_payments_active AS SELECT * FROM payments WHERE deleted_at IS NULL;

-- ==== 権限付与（アプリケーションユーザー用） ====
GRANT SELECT ON v_members_active, v_invoices_active, v_payments_active TO app_user;

-- ==== コメント（任意） ====
COMMENT ON TABLE members  IS '会員マスタ（論理削除: deleted_at）';
COMMENT ON TABLE invoices IS '請求（①では入金と非連携）';
COMMENT ON TABLE payments IS '入金（①では請求と非連携）';
```

# 改訂版：10. バリデーション対応表（①段階）

> ※この章はAPI設計（入力バリデーション仕様）へ移行予定。DB制約との対応関係を確認するため暫定掲載。

## 10.1 共通方針

* **API（Controller/DTO）で厳格にチェック**し、DB制約は**最後の保険**として整合性を担保。
* エラーは **HTTP 400**、`code`/`message` を返却（例：`VAL-001`, `VAL-002`…）。
* ID（ULID）は**サーバ生成**。クライアントからの入力は不可。

---

## 10.2 Members（会員）

| ------------- | ------ | --------------- | ---------------------------------- | -------------------------------------------- | -------------------------------------------------------------------------------- |
| `code`        | 会員コード  | `members.code`  | 必須／長さ1〜50／前後空白除去／記号可（規約に応じて正規表現可）  | **部分一意**（`ux_members__code_active`）／NOT NULL | `VAL-001: 会員コードを入力してください`、`VAL-002: 会員コードは50文字以内で入力してください`、`VAL-003: 既に使用されています` |

| ------------- | ------ | ----------------------- | ------------------------------------------------- | --------------------- | ---------------------------------------------------- | ---------------------------------- | ---------------------------- | ---------------------- |
| `memberId`    | 会員ID   | `invoices.member_id`    | 必須／ULID形式                                         | FK→`members(id)`      | `VAL-101: 会員IDが不正です`                                 |                                    |                              |                        |

| `description` | 明細/備考  | `invoices.description`  | 任意／上限（例：≤ 10000）                                  | なし                    | なし                                                   |                                    |                              |                        |
| `status`      | ステータス  | `invoices.status`       | 必須／列挙：`DRAFT                                      | ISSUED                | CANCELLED                                            | REVISED`（①は`ISSUED/CANCELLED`で運用可） | `CHECK (status in (...))` 推奨 | `VAL-107: ステータス値が不正です` |

**Spring Validation例（DTO）**

```java
public enum InvoiceStatus { DRAFT, ISSUED, CANCELLED, REVISED }

public record InvoiceUpsertRequest(
  @NotBlank String memberId,
  @NotNull @PastOrPresent LocalDate invoiceDate,
  @Nullable LocalDate dueDate,
  @NotNull @PositiveOrZero BigInteger amount,
  @NotBlank @Size(max=200) String title,
  @Size(max=10000) @Nullable String description,
  @NotNull InvoiceStatus status
) {}
// 期日チェック（推奨）は @AssertTrue かカスタムバリデータで：due==null || !due.isBefore(invoiceDate)
```

## 10.5 エラー設計（例）

* 形式：`{ "code": "VAL-105", "message": "請求額は0以上で入力してください", "field": "amount" }`
* 原因がDB一意制約の場合（例：会員コード重複）も、**例外ハンドラ**で上記形式に正規化して返却。

## 12. 運用・移行メモ（簡易）
- Flyway：本設計は **V1__init.sql** として投入  
- 監査トリガは**全テーブル共通**関数を使用（スキーマ増でも再利用）
- 本番導入時：`statement_timeout` や `timezone` はアプリ側でJDBC接続時に明示  
- 文字コード：UTF-8、照合順序はPostgreSQL既定（日本語LIKEは`ILIKE`等で対処）
