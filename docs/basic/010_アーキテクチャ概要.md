# アーキテクチャ概要

## 1. システム構成図（概要）
[`Client`] → [`Spring Boot API`] → [`PostgreSQL(DB)`]

## 2. 構成要素
| 層 | 役割 | 主な内容 |
|----|------|----------|
| Controller | APIエンドポイント定義 | DTO受け取り・レスポンス返却 |
| Application | ビジネスユースケース制御 | トランザクション・Service呼出 |
| Domain | 業務ロジック層 | Entity・ValueObject・DomainService |
| Infra | 外部I/O層 | Repository・DBアクセス・API通信 |
| Config | 設定層 | Security / Validation / ExceptionHandler 等 |

## 3. データフロー（請求登録例）
1. Client から `POST /api/v1/bills`  
2. Controller で DTO を受信・検証  
3. Application Service でドメインロジック実行  
4. Repository により DB 永続化  
5. 登録結果DTOを返却

## 4. 環境構成
| 環境 | URL | 備考 |
|------|-----|------|
| https | https://localhost:8443 | 開発用（自己署名証明書） |
| dev | https://dev.example.com | ステージング |
| prod | https://api.example.com | 本番 |

## 5. 採用技術の理由
- Spring Boot: 高生産性、Actuator/Validationの統合
- PostgreSQL: 安定・OSS・JSON対応
- Flyway: DB移行の再現性確保
- Gradle: シンプルなビルド定義
